# MediMate 요구사항 정의서

| 항목 | 내용 |
|---|---|
| 프로젝트 | 메디메이트(MediMate) – 디지털 소외계층을 위한 OCR·AI 기반 복약 관리 플랫폼 |
| 과정 | 2026-2 알파프로젝트 Ⅰ (15주, 9학점) / 지도교수 배홍균 |
| 팀 | 정영미(팀장), 신정민, 신지은 – 국민대학교 소프트웨어학부 |
| 버전 | v1.0 (2026-09-27) |

---

## 1. 개요

### 1.1 배경
시각장애인(약 25만 명)과 65세 이상 고령층(약 1,000만 명)은 작은 글씨, 병원·약국마다 다른 약봉투·처방전 양식 때문에 복약 정보(약품명, 용법·용량, 복용 시간)를 정확히 확인하기 어렵다. 기존 복약 앱은 약품명을 직접 검색·입력하는 방식이라, **정보를 읽는 것 자체가 어려운 사용자에게는 출발점부터 장벽**이 된다.

### 1.2 목표
1. **촬영 한 번으로 등록** – 약봉투·처방전을 찍으면 복약 정보가 자동으로 구조화·등록된다.
2. **화면을 보지 않고도 이용** – 모든 핵심 정보를 한국어 음성으로 안내하고, 스크린 리더(TalkBack)와 호환된다.
3. **낱알도 확인** – 포장 없이 보관된 알약을 촬영하면 후보 약품과 정보를 안내한다.
4. **복용까지 연결** – 복약 알림, 복용 체크, 맞춤 영양제 추천. (보호자 원격 확인은 v2 추후 업데이트, §11)
5. **실사용 검증** – 노인복지관 시범 운영 후 Google Play 정식 출시.

### 1.3 범위

| 포함 | 제외 |
|---|---|
| Android 앱 (Android 8.0 / API 26 이상) | iOS 앱 |
| Spring Boot 백엔드, 알약 식별 서비스 | 병원·약국 EMR/처방 시스템 연동 |
| 약봉투·처방전 OCR 등록, 낱알 식별 | 전자처방전·QR 처방 연동 |
| 복약 알림, 영양제 추천 | 진단·처방 변경 권고 등 의료 행위 |
| 식약처 공공데이터 연동 | 결제·구독 |
| 로그인(Google·카카오·전화번호), 재설치 복원 | **보호자 연결·원격 확인·미복용 통지 → v2 (§11)** |

**릴리스 구분**
- **v1 (학기 내 출시)**: 본 문서 §3–§10의 요구사항. 사용자 한 명이 자신의 약을 관리한다.
- **v2 (추후 업데이트)**: 보호자 기능과 이를 위한 푸시 알림(§11). v1에서 복용 기록을 서버에 계속 저장하므로, v2에서 보호자를 연결하면 과거 기록도 바로 볼 수 있다.

### 1.4 용어

| 용어 | 정의 |
|---|---|
| 약봉투 | 약국에서 조제약과 함께 주는 봉투/복약안내문. 약품명, 1회 투약량, 1일 횟수, 총 일수 등이 인쇄됨 |
| 처방전 | 병·의원이 발행하는 처방 내역 문서 |
| 낱알 | 포장 없이 보관된 알약 1정/1캡슐 |
| 각인 | 알약 표면의 문자·기호 (식약처 `PRINT_FRONT/PRINT_BACK`) |
| 복약 일정 | 약 하나에 대한 복용 시각·기간 규칙 |
| 복용 이벤트 | 일정에서 생성된 개별 복용 예정 1건 (예: 9/27 08:00 A약) |
| 피보호자 / 보호자 (v2) | 앱으로 약을 관리받는 사용자 / 그 복용 현황을 원격 확인하는 가족·요양보호사 |
| 구조화 결과 | OCR 텍스트를 AI가 약품 단위 JSON으로 정리한 결과 |

## 2. 이해관계자와 사용자

### 2.1 페르소나

| 페르소나 | 특성 | 핵심 요구 |
|---|---|---|
| **P1. 시각장애인** (전맹·저시력) | TalkBack 사용, 화면 확인 불가 또는 제한 | 음성 인터페이스 필수, 스크린 리더 호환, **간결한 음성 안내**, 촬영 시 음성 가이드 |
| **P2. 고령층** (70대, 다제 복용) | 노안, 스마트폰 조작 미숙, 약 5종 이상 복용 | **큰 글씨와 아이콘, 단순한 메뉴, 선명한 색 대비, 최소한의 터치** |
| **P3. 보호자** (자녀·요양보호사) – **v2 대상** | 원거리 거주, 일반적인 앱 사용 가능 | 복용 시간 알림, **복용 여부 확인**, 미복용 시 통지 |

### 2.2 기타 이해관계자
- 지도교수·교육혁신원: 주차별 산출물, 중간·최종 평가
- 노인복지관: 현장 시범 운영 장소, 사용자 모집
- 외부 서비스: NAVER Cloud(CLOVA OCR, SENS 문자), AWS(Bedrock), 식품의약품안전처(공공데이터), Google(로그인, Play), Kakao(카카오 로그인)

## 3. 기능 요구사항

### 3.1 계정·온보딩 (FR-AUTH)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-AUTH-01 | 첫 실행 시 앱은 **음성으로** 서비스와 사용 방법을 안내하고, 접근성 모드(음성 중심 / 큰 글씨 / 표준)를 고르게 한다. TalkBack이 켜져 있으면 음성 중심 모드를 기본 선택한다. | P0 |
| FR-AUTH-02 | 로그인 수단은 **Google 계정, 카카오 계정, 전화번호(SMS 인증)** 세 가지를 제공한다. 로그인 화면에는 큰 버튼 세 개만 두고 각 버튼을 음성으로 안내한다. 비밀번호는 쓰지 않는다. | P0 |
| FR-AUTH-04 | 건강 정보(출생연도, 성별, 보유 질환, 알레르기, 임신 여부)는 **선택 입력**이며, 입력 전 민감정보 수집 동의를 별도로 받는다. | P1 |
| FR-AUTH-05 | 사용자는 계정과 모든 데이터를 삭제할 수 있다. | P1 |
| FR-AUTH-06 | **앱을 지웠다 다시 깔거나 기기를 바꿔도** 같은 수단으로 로그인하면 약, 일정, 복용 기록, 설정이 모두 복원되고 알람이 다시 등록된다. | P0 |
| FR-AUTH-07 | 한 계정에 로그인 수단을 여러 개 연결할 수 있다(설정 → 로그인 방법 추가). 마지막 남은 수단은 해제할 수 없다. | P1 |
| FR-AUTH-08 | 전화번호 인증번호는 SMS 자동 인식으로 입력 없이 채워지고, 자동 인식이 안 되면 숫자 버튼을 크게 보여 준다. 인증번호는 음성으로도 읽어 준다. | P0 |
| FR-AUTH-09 | 로그인은 계속 유지된다. 사용자가 직접 로그아웃하지 않는 한 90일 이상 앱을 안 써도 다시 로그인하지 않게 한다. | P0 |
| FR-AUTH-10 | 처음 로그인한 사용자에게 "예전에 메디메이트를 쓰신 적이 있나요?"를 묻는다. "있어요"를 고르면 다른 두 로그인 수단을 안내하고, 그 수단에 기존 계정이 있으면 방금 만든 빈 계정을 정리한 뒤 기존 계정으로 연결한다. | P1 |
| FR-AUTH-12 | 설정 화면에서 "지금 로그인한 방법"을 크게 보여 주고 음성으로 읽어 준다(예: "카카오로 로그인되어 있습니다"). 재설치 때 어떤 방법을 골라야 하는지 기억하도록 돕는다. | P1 |

> FR-AUTH-03(역할 선택)과 FR-AUTH-11(보호자 화면의 로그인 수단 표시)은 v2로 옮겼다(§11).

### 3.2 약봉투·처방전 인식 등록 (FR-SCAN)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-SCAN-01 | 홈 화면의 가장 큰 버튼 한 번으로 촬영 화면에 진입한다. | P0 |
| FR-SCAN-02 | 촬영 중 **음성·진동 가이드**를 제공한다: 밝기 부족, 흔들림, 문서가 화면에 다 들어오지 않음 등. 조건이 맞으면 자동 촬영하고, 수동 촬영 버튼도 제공한다. | P0 |
| FR-SCAN-03 | 서버는 이미지를 CLOVA OCR로 인식한다. 인식 실패(글자 없음, 저품질)이면 원인을 음성으로 알리고 재촬영을 안내한다. | P0 |
| FR-SCAN-04 | 서버는 OCR 결과를 Claude로 정제·구조화하여 약품별로 **약품명, 함량, 1회 투약량, 1일 횟수, 복용 시점(아침/점심/저녁/취침 전), 식전·식후, 총 일수, 복약 안내 문구**를 추출한다. | P0 |
| FR-SCAN-05 | 추출한 약품명은 식약처 허가 품목 DB와 대조하여 표준 품목에 연결한다. 연결되지 않거나 신뢰도가 낮은 항목은 **"확인 필요"** 로 표시한다. | P0 |
| FR-SCAN-06 | 결과는 **약 단위로 음성 낭독**되고 화면에 큰 글씨 카드로 표시된다. 사용자는 "맞아요 / 다시 찍기 / 고치기" 중 하나를 선택한다. | P0 |
| FR-SCAN-07 | 확인된 결과로 복약 일정(FR-SCHED-01)을 자동 생성한다. | P0 |
| FR-SCAN-08 | 처방전(약국 조제 전 문서)도 동일 흐름으로 인식한다. 처방전은 조제 일수·용법이 약봉투와 다를 수 있으므로 결과에 문서 종류를 표시한다. | P1 |
| FR-SCAN-09 | 주민등록번호 등 식별번호는 AI 전달 전 서버에서 **마스킹**하고 저장하지 않는다. 환자 이름은 추출하지 않는다. | P0 |
| FR-SCAN-10 | 인식 진행 중에는 2–3초 간격의 진행음과 "분석 중입니다" 안내를 제공한다. | P0 |
| FR-SCAN-11 | 원본 이미지는 기본적으로 처리 후 즉시 폐기한다. "품질 개선에 사진 제공"에 동의한 경우에만 최대 30일 보관한다. | P1 |

### 3.3 낱알 식별 (FR-PILL)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-PILL-01 | 알약 앞면(필수)과 뒷면(선택)을 촬영한다. 촬영 전 "어두운 단색 바탕 위에 올려 주세요" 등 촬영 조건을 음성으로 안내한다. | P0 |
| FR-PILL-02 | 서버는 모양, 색상, 각인, 분할선, 제형을 추정하고 식약처 낱알식별 DB와 비교해 **후보 Top-5**를 산출한다. | P0 |
| FR-PILL-03 | 사용자가 현재 복용 중으로 등록한 약은 후보 순위에 가산점을 준다. | P1 |
| FR-PILL-04 | 결과는 "가장 비슷한 약은 ○○입니다"처럼 **단정하지 않는 표현**으로 안내하고, 신뢰도가 낮으면 후보 개수와 함께 약사 확인을 권한다. | P0 |
| FR-PILL-05 | 후보를 선택하면 약품명, 효능, 복용법, 주의사항을 음성으로 안내한다(FR-DRUG). | P0 |
| FR-PILL-06 | 후보의 식약처 참조 이미지를 크게 보여 주어 저시력 사용자나 가족이 직접 비교할 수 있게 한다. | P1 |

### 3.4 약품 정보 (FR-DRUG)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-DRUG-01 | 등록 약 또는 식별 약에 대해 효능, 복용법, 주의사항, 부작용, 보관법을 식약처 "e약은요" 데이터 기준으로 제공한다. | P0 |
| FR-DRUG-02 | 음성 안내는 **요약본(30초 이내)** 을 먼저 읽고, "자세히 듣기"를 선택하면 전체를 읽는다. | P1 |
| FR-DRUG-03 | 등록된 약들 사이의 **병용금기**(식약처 DUR)가 있으면 등록 시 경고한다. | P1 |
| FR-DRUG-04 | 약품 정보 출처(식약처)와 기준일을 표시한다. | P1 |

### 3.5 복약 일정·알림 (FR-SCHED)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-SCHED-01 | 구조화 결과의 복용 시점을 사용자별 기본 시각(예: 아침 08:00, 점심 12:30, 저녁 18:30, 취침 전 22:00)으로 변환해 일정을 만든다. 기본 시각은 사용자가 바꿀 수 있다. | P0 |
| FR-SCHED-02 | 복용 시각에 **기기 로컬 알림**(소리·진동·음성)을 울린다. 네트워크가 없어도 동작해야 한다. | P0 |
| FR-SCHED-03 | 알림에서 바로 "먹었어요"를 누를 수 있다. 같은 시각에 먹을 약은 한 알림으로 묶고 약 이름을 읽어 준다. | P0 |
| FR-SCHED-04 | 복용 체크가 없으면 설정 간격(기본 15분)으로 최대 2회 다시 알린다. | P1 |
| FR-SCHED-05 | 총 일수가 끝나면 일정을 자동 종료하고, 종료 하루 전 "내일로 ○○약이 끝납니다"를 안내한다. | P1 |
| FR-SCHED-06 | 오늘 복용 현황(먹은 약 / 남은 약)을 홈 화면에서 확인하고 음성으로 들을 수 있다. | P0 |
| FR-SCHED-07 | 오프라인에서 기록한 복용 체크는 네트워크 복구 시 서버와 동기화한다. | P0 |
| FR-SCHED-08 | 온보딩에서 알림·정확한 알람 권한과 배터리 최적화 제외를 음성으로 안내해 켜게 한다. 권한이 꺼져 있으면 홈 화면 맨 위에 "알림이 늦거나 울리지 않을 수 있습니다"를 표시하고 설정으로 바로 가는 버튼을 둔다. (v1에는 서버 백업 푸시가 없음) | P0 |

### 3.6 보호자 (FR-GUARD) – v2로 이동
보호자 연결, 복용 현황 확인, 미복용 통지는 v2 추후 업데이트로 옮겼다. 요구사항은 §11.1에 있다.

### 3.7 맞춤 영양제 추천 (FR-SUPP)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-SUPP-01 | 사용자의 복용 약, 선택 입력한 건강 정보, 관심사(뼈 건강, 눈 건강 등)를 바탕으로 건강기능식품 기능성 원료를 추천한다. | P1 |
| FR-SUPP-02 | 복용 중인 약과 **상호작용 주의가 있는 원료는 추천에서 제외**하고, 제외 사유를 알려 준다(예: 와파린 복용 시 비타민K·오메가3 주의). | P1 |

## 5. 유스케이스

### UC-01 약봉투로 약 등록
- **액터**: 사용자(P1/P2)
- **사전 조건**: 앱 설치, 로그인 완료, 카메라 권한 허용
- **기본 흐름**
  1. 사용자가 홈의 "약봉투 찍기"를 누른다.
  2. 앱이 "약봉투를 화면 가운데에 두세요"라고 안내하고, 밝기·흔들림·문서 영역을 실시간 확인한다.
  3. 조건이 맞으면 자동 촬영 → 이미지 축소 → 서버 업로드 → 진행음 재생.
  4. 서버: CLOVA OCR → 식별번호 마스킹 → Claude 구조화 → 식약처 품목 대조 → 음성 문장 생성.
  5. 앱이 "약 3개를 찾았습니다. 첫 번째 약, …"을 읽고 카드를 표시한다.
  6. 사용자가 "맞아요"를 누르면 일정이 생성되고 "내일 아침 8시에 알려 드릴게요"를 안내한다.
- **대안 흐름**
  - 3a. 30초 안에 조건이 맞지 않으면 수동 촬영을 안내한다.
  - 4a. 글자를 찾지 못함 → "글자가 잘 보이지 않습니다. 밝은 곳에서 다시 찍어 주세요."
  - 4b. AI 호출 실패 → 1회 자동 재시도 후 실패 시 "잠시 후 다시 시도해 주세요".
  - 5a. "확인 필요" 항목이 있음 → 해당 약을 먼저 알리고 "가족이나 약사에게 확인해 주세요"를 덧붙인다.
  - 6a. "고치기" → 약 단위로 항목을 수정(큰 버튼 선택형: 1회량 −/+, 시점 토글).
- **사후 조건**: 약·일정·첫 복용 이벤트가 로컬과 서버에 저장된다.

### UC-02 낱알 식별
1. "알약 알아보기" → 바탕·조명 안내 → 앞면 촬영 → (선택) 뒷면 촬영.
2. 서버: 알약 식별 서비스(분할·속성·각인·임베딩) + Claude 비전 관찰 → 후보 점수 → (저신뢰 시) Claude 재순위.
3. 앱: "가장 비슷한 약은 타이레놀정 500밀리그램입니다. 비슷한 후보가 2개 더 있습니다." → 후보 선택 시 약품 정보 낭독.
- 대안: 알약을 찾지 못함 → 바탕 안내 후 재촬영. 저신뢰 → 후보 이미지와 함께 약사 확인 권유.

### UC-03 복약 알림과 복용 체크
1. 예정 시각에 로컬 알람 → "아침 약 드실 시간입니다. 혈압약, 당뇨약 두 가지입니다."
2. 사용자가 알림의 "먹었어요"를 누른다 → 로컬 기록 → 서버 동기화.
- 대안: 체크 없음 → 15분 간격 재알림 2회 → 그래도 없으면 해당 복용은 "안 드심"으로 기록되고 홈의 오늘 현황에 표시.

### UC-04 보호자 연결·확인 – v2로 이동 (§11.2)

### UC-05 영양제 추천
1. 사용자가 관심 분야를 고른다(최대 2개, 큰 버튼).
2. 서버: 복용 약 성분 조회 → 상호작용 규칙으로 제외 → 기능성 원료 후보 → Claude로 쉬운 설명 생성(주어진 근거 안에서만).
3. 앱: 추천 3개와 제외 사유, 상담 권고를 읽어 준다.

### UC-06 첫 로그인과 재설치 후 복원
- **액터**: 사용자
- **기본 흐름 (첫 사용)**
  1. 첫 실행 → 음성 소개 → 접근성 모드 선택(FR-AUTH-01).
  2. 로그인 화면: "구글로 시작", "카카오로 시작", "전화번호로 시작" 큰 버튼 세 개.
  3. 선택한 수단으로 인증 → 서버가 계정을 만들고 토큰 발급.
  4. "예전에 메디메이트를 쓰신 적이 있나요?" → "처음이에요" → 알림 권한 안내(FR-SCHED-08) → 홈.
- **대안 흐름**
  - 2a. 전화번호: 번호 입력(큰 숫자 키패드) → 인증번호 SMS → 자동 입력 → 확인.
  - 3a. 인증 취소·실패 → "로그인하지 못했습니다. 다른 방법을 고르시거나 다시 시도해 주세요."
  - 4a. "있어요" → 다른 두 수단 안내 → 기존 계정이 있으면 방금 만든 빈 계정을 정리하고 기존 계정으로 전환(FR-AUTH-10).
- **재설치·기기 변경**
  1. 새로 설치한 앱에서 예전과 같은 수단으로 로그인.
  2. 서버가 기존 계정을 찾아 토큰 발급 → 앱이 전체 데이터 수신 → Room 복원 → 알람 재등록.
  3. "예전 기록을 불러왔습니다. 드시는 약 네 가지, 다음 복용은 저녁 여섯 시 삼십 분입니다."
- **사후 조건**: 기존 약·일정·기록·설정 유지. 앱 삭제 직전 오프라인 상태로 서버에 올라가지 못한 복용 체크만 사라질 수 있다.

## 11. 추후 업데이트 (v2) – 보호자 기능

v1 출시 후 업데이트로 추가한다. v1은 복용 기록을 서버에 계속 저장하므로, v2에서 보호자를 연결하면 연결 이전 기록도 바로 볼 수 있다.

### 11.1 기능 요구사항

| ID | 요구사항 | 우선(v2 내) |
|---|---|---|
| FR-AUTH-03 | 역할(피보호자 / 보호자)을 선택한다. 한 계정이 두 역할을 겸할 수 있다. v1 사용자는 업데이트 후 피보호자로 간주한다. | 필수 |
| FR-AUTH-11 | 보호자 화면에 피보호자가 쓰는 로그인 수단(예: "카카오")을 표시해, 피보호자가 잊었을 때 보호자가 알려 줄 수 있게 한다. | 권장 |
| FR-GUARD-01 | 피보호자 앱에서 6자리 초대 코드를 만들고(음성으로 읽어 줌), 보호자가 입력하면 연결된다. 코드는 10분 후 만료된다. | 필수 |
| FR-GUARD-02 | 보호자는 피보호자의 오늘·최근 7일 복용 현황을 본다. | 필수 |
| FR-GUARD-03 | 복용 예정 시각 후 설정 시간(기본 30분)까지 체크가 없으면 보호자에게 푸시 알림을 보낸다. | 필수 |
| FR-GUARD-04 | 보호자는 피보호자의 약 목록과 일정을 조회하고, 피보호자가 허용한 경우 수정할 수 있다. | 권장 |
| FR-GUARD-05 | 피보호자는 언제든 연결을 끊을 수 있다. | 필수 |
| FR-GUARD-06 | 약봉투 인식 결과에 "확인 필요" 약이 있으면 연결된 보호자에게 확인 요청을 보낸다. | 권장 |
| FR-SCHED-09 | 정확한 알람 권한이 없는 기기에는 서버가 푸시로 백업 알림을 보낸다. | 권장 |

### 11.2 유스케이스 UC-04 보호자 연결·확인
1. 피보호자: 설정 → "보호자 연결" → 6자리 코드 음성 안내.
2. 보호자: 앱 설치 → 로그인 → 보호자 역할 → 코드 입력 → 연결.
3. 보호자 홈: 피보호자별 오늘 복용률, 미복용 목록, 최근 7일 기록.
4. 미복용: 예정 시각 + 30분까지 체크가 없으면 보호자에게 "○○님이 아침 8시 약을 아직 드시지 않았습니다." 푸시.

### 11.3 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-REL-04 | 보호자 미복용 푸시는 조건 발생 후 5분 이내 발송 |
| NFR-SEC-05 | 보호자는 연결된 피보호자의 데이터만 조회할 수 있다(서버에서 권한 검사). |
| NFR-SEC-09 | 보호자 연결 전 피보호자에게 공유되는 정보(약 목록, 복용 기록)를 음성으로 알리고 동의를 받는다. |
